## 1. 端到端为什么还是慢：结构变了

| 分量 | page_scan | DCI | 差 |
|---|---|---|---|
| TTFT（每问付一次） | 3.6138 s | 3.3062 s | **+0.3076 s** |
| decode / 其余（`total − ttft`） | 0.4575 s | 0.4927 s | **−0.0352 s** |
| 合计 | 4.0713 s | 3.7989 s | +0.2723 s |

**和 `16_` 相比，结构变了：TTFT 之后的那个分量，符号翻过来了。**
`16_`：+0.0099 s（page_scan 略慢）；现在：**−0.0352 s（page_scan 略快）**。
于是端到端的全部差距都来自 TTFT，而且**只有 TTFT**——`total_s` 差 +0.2723 s，
TTFT 差 +0.3076 s，decode 分量倒贴 0.0352 s。这和 TPOT 领先 22.28% 是自洽的。

> 注：`total − ttft` 是**近似**分量，它包含每问的固定开销（打分、分词等），
> 不等于 `TPOT × 生成 token 数`（后者会更大）。用它只看**符号和量级**，不要当精确分解。

**盈亏平衡点：每问约 12.6 个生成 token**，即两条线在
`n* = (TTFT_ps − TTFT_dci) / (TPOT_dci − TPOT_ps) = 0.3076 / 0.0244 = 12.6`
处相交。`16_` 的同一算式按其次优数字约 26–30。**平衡点砍掉了一半以上。**

> ⚠ **12.6 是一个线性模型的交点，不是测量。** 它假设两臂有一个共同的每问常数项；
> 把观测 token 数代回去，模型给 +0.17 s 而实测 +0.27 s，**残差约 0.10 s**——
> 相对 0.27 s 的差不算小，所以这个数只该按「**大约 12–15**」引用，不要引用小数位。
> 另外**不要用 0.2723 那个总差当分子**：总差里已经含了 page_scan 多说 0.84 个 token 的代价，
> 用它除以 0.0244 会重复计数，得到偏小的 11.2。

**本基准每问实际生成 5.93 个 token**（8 臂 × 40 行总均值；page_scan 臂 **6.350**，
DCI 臂 5.300–5.650）。按 12.6 与 5.93 算，**还差约 2.1 倍，仍不达标**，
但已经从「怎么都追不上」变成「再多生成一倍就翻盘」。

> ⚠ `16_` 写的「hotpotqa 生成 **5.82**」**在本轮数据上复现不出来**（任何一臂、任何均值都不是 5.82；
> 本轮是 5.93）。5.82 是更早那轮的数，本轮不要混用。**而且「hotpotqa 生成多少 token」
> 本身是臂相关的**：page_scan 6.35、DCI 5.51，所以引用时请把两个臂分开写。

**生成 token 数是本轮唯一一个对 page_scan 不利的、且不受它支配的量：**
page_scan 四个臂全是 **6.350**（完全确定），DCI 四个臂是 5.300/5.475/5.625/5.650（**自己就不确定**）。
所以「每问慢 7.17%」里有相当一部分是它多说的那 0.84 个 token 换来的。

**效应（22.28%）是最大 null 的 4.76 倍、中位 null 的约 11.5 倍**（`16_` 是 2.8 倍）。

> 两序都要取较大者再比：初版这里对 page_scan 取了较大的那一序（4.68%），
> 对 DCI 却取了较小的那一序（2.68%），**两个数不是同一种取法**。
> 统一的取法是 4.69% vs 2.76%。

**槽位漂移没有出现。** 斜率和相关系数见 §0；作为对照，`16_` 的窗口里 DCI 在 A 段是 0.7%、
B 段是 6.7% —— 那才是需要保守修正的信号。这次两段的同码 null 落在同一分布里。

**诚实记录：少数同码 null 达到了名义显著。** ps2/ps3 的 TTFT（gap=1，p=0.038）、
dci2/dci3 的 TTFT 与 `total_s`（**gap=3**，p=0.0064）、dci3/dci4 的 `total_s`（gap=1，p=0.017）。
36 个 null 比较里出现几个属预期。

> ⚠ **初版这里说「达到显著的都是槽位相邻（gap=1）的配对」，这是错的**——
> **其中最显著的一个（dci2/dci3，p=0.0064）是 gap=3。** 只能退到更弱的那句：
> 达到显著的都不是跨窗口端点的那几对（ps1/ps4 是 gap=7），这与单调漂移不一致。
> 这不构成趋势证据，但它说明**单个配对的真实噪声地板约 2%**，
> 这也是本报告坚持引用「16/16 全同向」而不引用任何单个配对的原因。

**效应相对地板：最小效应 19.43%，是最大同码 null 4.68% 的 4.1 倍。** 即使取最不利配对，判决不变。

## 4. 一次已披露的窗口重叠（诚实记录，判定：不影响结论）

贪心方向的第二个 agent 在我校正窗口安排之前，已经按早先的「你先用」指令取了 GPU，
在 **约 04:35–04:40** 跑了两条正确性检查（`dtype_probe.py`、`gpu_identity.py`）。
我的 `ps4` 臂是 **04:36:06–04:39:38**，**重叠了**。

**判定：不需要重测。但下面这一节被独立核查过一次，初版的四条「证据」里有两条要撤回或改写，
且**漏报了一个反向的重叠**。以改后的版本为准。**

**先修正时间线（驱动日志 + `.mem` 采样器）：**
`dci4` 是 **04:32:46–04:36:14**，`ps4` 是 **04:36:15–04:39:38/46**。
初版把 `ps4` 的起点写成 04:36:06——那是 **`dci4.jsonl` 的 mtime**，不是 ps4 的开始。

**保留的证据（这三条承载结论）：**

1. **`ps4` 没有异常名次。** TTFT 3.6321 在 {3.6153, 3.5679, **3.6398**} 里排第三（最差的是 ps3），
   TPOT 84.367 在 {83.278, 85.997, **87.179**} 里排第二（最差的是 ps3，而 ps3 与本次重叠无关）。
2. **`ps4` 对 `ps1` 的逐行 TTFT 差没有污染签名。** 均值 **+0.0169 s**（sd 0.172，19/40 为正）。
   本项目此前实测过的 CPU 争用是 **0.6–2.2 s/行**；真发生的话这里会是压倒性的正值。
3. **删掉 `ps4` 结论不变**：剩下 3×4 = 12 个配对依旧全部同向
   （合并 TPOT 比值 0.782，对比含 ps4 的 0.777——**去掉它反而更保守，方向不变**）。

**撤回 / 改写：**

- **❌ 撤回初版的「第 1 条：文件系统证据把窗口卡在 04:35–04:40」。** 那两条脚本
  （`dtype_probe.py` 04:35:04、`gpu_identity.py` 04:35:07）**只往 stdout 打印、不写任何文件**。
  所以「04:35 之后没有新文件」只能界定对方**最后一次创建文件**的时间，
  **界定不了这两个脚本跑了多久**。这是把一次未经支持的推断当成了证据。
- **⚠ 初版的符号写反了。** 那个 −0.46% 是 `ps1/ps4` 这一序（`(ps1−ps4)/ps4`）；
  按「ps4 相对 ps1」读应该是 **+0.47%**。量级对，方向说反了。
- **⚠ 初版把暴露面说成单边的，这是不完整的。** 我写「ps4 是 page_scan 臂，所以污染只压低
  page_scan」——但按对方自述的 04:35–04:40 窗口，**`dci4`（一个 DCI 臂）也重叠了约一分钟**
  （04:32:46–04:36:14）。**那条重叠的方向是抬高 DCI，也就是对 page_scan 有利。**
  所以净方向并不是单向不利于我方的。`dci4` 本身同样没有异常名次
  （TTFT 在 DCI 四臂里第二快，TPOT 第三），但**这件事初版漏报了，应当披露**。

**结论不变：不需要重测。** 没有任何一个臂显示出本项目已知量级（0.6–2.2 s/行）的污染签名，
且无论保留还是删除 `ps4`、无论两个重叠的净方向如何，16 个配对的方向都一致。
**但承载这个结论的是「无签名 + 结论对臂的取舍不敏感」，不是初版第 1 条那个文件系统论证。**

**教训（并入台账）：** `flock` 只做串行化、不做互斥声明。给另一个 agent 的窗口安排
必须**先发**、且校正要**立刻**发；一个「你先用」的旧指令会在几小时后仍然生效。
